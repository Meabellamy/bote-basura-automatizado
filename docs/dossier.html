1. Descripción del Sistema

🎯 Objetivo del proyecto Diseñar e implementar un bote de basura inteligente que detecte automáticamente la presencia de una mano mediante un sensor ultrasónico y abra su tapa con un servomotor, manteniéndola abierta durante el tiempo necesario para depositar la basura, para después cerrarla de forma autónoma.

El sistema emplea un microcontrolador Arduino UNO (fase Decode / CPU) que coordina el sensor ultrasónico HC-SR04 (fase Fetch / Entrada) y el servomotor SG-90 (fase Execute / Salida). Todo el código respeta las convenciones ANSI/ISO C++11.

1.1 Principio de funcionamiento

El sensor ultrasónico emite un pulso de ultrasonido de 10 µs cada 100 ms. Si el eco regresa en un tiempo que corresponda a una distancia ≤ 20 cm, el sistema interpreta que existe un objeto (mano del usuario) frente al sensor. En ese momento el servomotor gira de 0 ° (tapa cerrada) a 90 ° (tapa abierta). Después de 3 segundos el servo regresa a 0 ° cerrando la tapa automáticamente.

5. Código Fuente — bote_basura.ino

El código sigue las convenciones ANSI/ISO C++11: uso de tipos de ancho fijo (uint8_t, uint16_t, uint32_t), constantes tipadas con sufijos U / UL, prototipos explícitos, documentación Doxygen, y separación clara en secciones. 

/**
 * @file        bote_basura.ino
 * @project     Dossier — Bote de Basura Automatizado
 * @version     1.0.0   |   @standard  ANSI / ISO C++11
 * @authors     Meave Diaz Armando Abdiel · Sandoval Juan Manuel
 */

#include <Servo.h>

/* ── Constantes de configuración ─────────────────────────── */
static const uint8_t  PIN_TRIG            = 9U;
static const uint8_t  PIN_ECHO            = 10U;
static const uint8_t  PIN_SERVO           = 6U;

static const uint8_t  ANGULO_CERRADO      = 0U;
static const uint8_t  ANGULO_ABIERTO      = 90U;
static const uint16_t DISTANCIA_UMBRAL_CM = 20U;
static const uint32_t DELAY_TAPA_ABIERTA  = 3000UL;
static const uint32_t DELAY_MUESTREO_MS   = 100UL;
static const float    VEL_SONIDO          = 0.034f;

/* ── Objeto global ───────────────────────────────────────── */
Servo servoTapa;

/* ── Prototipos ──────────────────────────────────────────── */
uint16_t medirDistancia(void);
void     abrirTapa(void);
void     cerrarTapa(void);

void setup(void) {
    pinMode(PIN_TRIG, OUTPUT); digitalWrite(PIN_TRIG, LOW);
    pinMode(PIN_ECHO, INPUT);
    servoTapa.attach(PIN_SERVO);
    cerrarTapa();
    Serial.begin(9600);
}

void loop(void) {
    uint16_t d = medirDistancia();
    if (d > 0U && d <= DISTANCIA_UMBRAL_CM) {
        abrirTapa();
        delay(DELAY_TAPA_ABIERTA);
        cerrarTapa();
    }
    delay(DELAY_MUESTREO_MS);
}

uint16_t medirDistancia(void) {
    digitalWrite(PIN_TRIG, LOW);  delayMicroseconds(2U);
    digitalWrite(PIN_TRIG, HIGH); delayMicroseconds(10U);
    digitalWrite(PIN_TRIG, LOW);
    unsigned long t = pulseIn(PIN_ECHO, HIGH, 30000UL);
    if (t == 0UL) return 0U;
    return static_cast<uint16_t>((t * VEL_SONIDO) / 2.0f);
}

void abrirTapa(void)  { servoTapa.write(ANGULO_ABIERTO);  }
void cerrarTapa(void) { servoTapa.write(ANGULO_CERRADO); }

8. 🧠 Fase 1 — Disección del Cerebro (ATmega328P)

Objetivo Perder el miedo al hardware. El Arduino es un chip ATmega328P. En esta sección entendemos cómo piensa el microcontrolador que gobierna nuestro bote de basura.
1

¿Por qué 8 bits? — La restricción fundamental
Su "boca" procesa datos en bloques de 8 ceros y unos (valores de 0 a 255). En este contexto, la memoria es oro: escribir código eficiente sin desperdicios es vital para no saturar la máquina. Por eso en este proyecto usamos tipos de ancho fijo (uint8_t, uint16_t) en lugar de tipos genéricos que consumen más bytes de los necesarios.

2

Harvard vs. Von Neumann — Ventaja táctica del micro

Arquitectura Memoria de programa Memoria de datos Acceso simultáneo
Von Neumann (tu laptop) Compartida — mismo bus ✗ No
Harvard (ATmega328P) Flash 32 KB (exclusiva) SRAM 2 KB (exclusiva) ✔ Sí

El ATmega328P lee una instrucción del Flash al mismo tiempo que accede a un dato en SRAM — siendo ultra rápido para sistemas en tiempo real como la detección de proximidad de nuestro bote.

3

Registros de Control — Los cajones del silicio
El microcontrolador no sabe qué es un "pin 9" en abstracto. Internamente usa registros de 8 bits (p. ej. DDRB, PORTB) para configurarse. Cuando escribimos pinMode(PIN_TRIG, OUTPUT), el compilador traduce esa instrucción a una modificación directa del bit correspondiente en el registro DDRB, diciéndole físicamente al silicio: "Conviértete en un pin de salida de voltaje".

Ejemplo en registro directo (equivalente a pinMode(9, OUTPUT)): DDRB |= (1 << PB1); // Pin D9 → salida

📝 Parte 2 — Bitácora del Ingeniero Senior

Pregunta de análisis — respuesta con sus propias palabras:

Si el ATmega328P procesa 8 bits y tiene poca memoria, ¿por qué usamos C/C++ embebido en lugar de Python o Java? 🤔

💬 Respuesta (análisis del equipo):

Python y Java requieren un intérprete o máquina virtual que consume cientos de kilobytes de RAM y necesita un sistema operativo subyacente. El ATmega328P solo tiene 2 KB de SRAM y 32 KB de Flash — menos que un archivo de texto moderno.

C/C++ compila directamente a código máquina AVR: cada instrucción escrita se convierte en opcodes que el procesador ejecuta sin intermediarios. Esto permite:

  • Control total sobre cada byte de memoria.
  • Tiempos de respuesta deterministas (crítico para el sensor ultrasónico).
  • Acceso directo a registros de hardware (DDRx, PORTx).
  • Binario final de pocos KB — cabe holgadamente en el Flash.
